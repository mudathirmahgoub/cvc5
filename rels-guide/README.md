# A guide to cvc5's relational solver

`theory_sets_rels_guide.pdf` (source `theory_sets_rels_guide.tex`) explains
`src/theory/sets/theory_sets_rels.{h,cpp}` for a newcomer:

* Part I  - the theory T_R and the CADE'17 calculus (Meng/Reynolds/Tinelli/Barrett)
* Part II - the data structures declared in the header, with lifetimes
* Part III- the algorithms in pseudocode, rule by rule, transitive closure in depth
* Part IV - the investigation: should `buildTCGraphForRel` be called once or twice?

Build with `pdflatex theory_sets_rels_guide.tex` (twice, for cross-references).

## Investigation outcome

Once, up front, immediately after `collectRelsInfo`. A second call rebuilds
`d_tcr_tcGraph[tc_rel]` from the base relation's members alone, discarding the
closure edges `applyTCRule` has added in the meantime, which is why `main` has to
guard both of its call sites (`d_rel_nodes` and `d_rRep_tcGraph` double as
"already built" markers). Building once makes the guards unnecessary.

Implemented in `8bcdf3239` on branch `build-trc-graph-once`: one unconditional
pass over every `rel.tclosure` term at the top of `check()`, both previous call
sites deleted, `buildTCGraphForRel` no longer inserting empty entries into the
membership maps via `operator[]`, and `regress0/rels/rel_tc_7.cvc.smt2` moved out
of `regression_disabled_tests`.

The two configurations compared throughout are `main` (`5cc03f4b9`) and _once_
(`8bcdf3239`). They are **behaviourally and performance-indistinguishable**, so
the case for the change is structural, not a speedup:

* `Invariant 4` ("the graph is built once, before any rule runs, and only added
  to afterwards") holds by construction, for every closure term, instead of per
  base representative and only because Phase A precedes Phase B.
* Correctness stops depending on bookkeeping state that looks like a redundant
  optimisation at the call site.
* The `applyTCRule` guard's representative bug goes away: it tested
  `find(tc_rel[0])` where `buildTCGraphForRel` looks up the representative, so
  the graph was missing during Phase A whenever the base relation was not its own
  representative.

## Measurements

100 in-tree `rels` benchmarks plus the 67 generated by `gen_stress.py`:

    answers differing                                    0 / 167
    theory::sets inference histograms differing          0 / 167
    wall time, 67 generated benchmarks         8.663s vs 8.594s  (1.01x)
    ctest -R rels                                       99 / 99 pass
    ctest -R "sets|rels|relation"                      303 / 303 pass
    fuzz_tc.py, seeds 1-3, 900 instances vs oracle    900 / 900 both, 0 diffs

The `benchmarks/A-E` family is the smallest set of formulas in which the graph
has to hold a base edge and a closure edge at once (A is
`regress1/rels/tc-overwrite-bug.smt2`), with B, C and D as controls; both
configurations answer all five correctly.

## Scripts

* `benchmarks/gen_stress.py <outdir>` - the 67 scaling and equal-relation
  benchmarks used in Part IV.
* `benchmarks/compare.py a=<bin> b=<bin> <timeout> <files...>` - differential
  status and timing table; `REPS=n` for repeated runs (reports the minimum).
* `benchmarks/fuzz_tc.py <seed> <n>` - differential test against an exact
  reachability oracle. Point it at two snapshots with `BASE_BIN` / `ONCE_BIN`
  (see Appendix B of the PDF for why copying the executable alone is not
  enough); `MAX_NODES` / `MAX_EDGES` set the instance size.
